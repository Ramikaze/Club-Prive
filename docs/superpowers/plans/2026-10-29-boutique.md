# Boutique Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sell cigars and champagne outside room sessions (« Boutique »), to day clients, regular clients and members, with a new « Associé » role owning one rayon each, a purchase history on every file, and the Boutique money visible apart in the Caisse.

**Architecture:** One new migration (V18) adds the associé role (users table rebuilt), a `kind` on members (membre / client / journalier), a `shop_sales` table and a `shop_sale_id` on charges and payments. A Boutique sale reuses the existing machinery: product charges (`insertCharge`, `moveStock`), one payment (`recordPayment`, card first) and refunds (`writeRefund`) for a cancellation. New server code lives in `worker/shop.js` (mixed into `Club` like `ledger.js` and `lounge.js`); the role rules live in one shared file, `shared/roles.js`, used by the worker and the front.

**Tech Stack:** React 18 + react-router 6 (Vite), Cloudflare Worker + Durable Object SQLite, `node:test` with `test/harness.js`.

**Spec:** `docs/superpowers/specs/2026-10-28-boutique-design.md` (approved by the owner 2026-10-29). Read it before any task. Private mockups (reference only, French): https://claude.ai/artifact/P41RTemHKe5X418XskRhkW (where the spec and a mockup disagree, the spec wins).

**Branch:** `feat/boutique`, created from `main`. The owner approves every commit, push, merge and deployment (see Global Constraints).

## Global Constraints

- Every screen is in French, in the app's current tone and layout, light and dark themes, usable on phone and tablet.
- The repository is public: no real phone number, no product photo, no manufacturer text in code, tests or seed.
- Database changes go through a new migration version: V18 (and later) in `worker/schema.js`. Existing data must not move: sessions, payments, tickets, past days' cash figures.
- Amounts are integers in hundredths (`UM = 100` in tests). Quantities are whole numbers from 1 to 99.
- Payment methods come from `settings.payment_methods`; `CARD_METHOD = 'Carte membre'` (`shared/rules.js`). The card balance never goes below 0. Stock is checked on the server. A closed day (`assertOpen`) refuses any money movement dated on it.
- Tests: `npm test` (`node --test test/*.test.js`) must stay fully green after every task; `npm run build` must succeed after every front-end task.
- Comments in English, matching the density and style of the surrounding code; user-facing text in French.
- Commits: one per task on `feat/boutique`, message in French in the repository's style (e.g. « Boutique : vente au comptoir »), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, merge or deploy without the owner's explicit yes.
- Rayon rule written in one place only: `ownsAccount` in `shared/roles.js`. Owner's decision (2026-11-06, spec « Règle du rayon en séance : pas de limite »): the rule applies only to the Boutique (selling, cancelling) and to products — file, price, photo and every stock change, up **and** down. In room sessions there is no rayon limit: an associé adds, cancels and refunds cigar and champagne lines like the administrator; the money still goes to the product's account. No session code calls `ownsAccount`.

## Review Focus

1. Two tablets selling the last cigar at the same time: the second sale must fail with `STOCK_INSUFFISANT` and leave no charge, no payment, no shop sale behind (Task 4 test `vente refusée sans trace quand le stock manque`).
2. A double tap on « Encaisser » (same `Idempotency-Key` sent twice) must create one sale and one payment (Task 4 test `double envoi : une seule vente`).
3. The hidden « Client journalier » row must never appear in members or clients lists, searches or renewals, and its file never opens (Task 3 tests `le client journalier n'apparaît nulle part`, `la fiche du client journalier ne s’ouvre pas`); in the payments export a day-client sale reads « Client journalier » with no member number and no personal data (Task 4 test `export des encaissements : client journalier sans donnée personnelle`).
4. A buyer deactivated after the screen loaded, or a regular client sent as « membre », must be refused by the server (Task 4 test `acheteur désactivé ou mauvais type refusé`).
5. An associé whose role or rayon changes while signed in must be signed out (Task 1 test `changer le rayon ferme les sessions`).

// A database at version 17 holding records made through the API: built with the first 17 migrations, then filled
// with every row of a database made on the current code (the V17 columns of each table only), as `v14Copy` does
// in test/wallet.test.js (~line 519). Imports: `nodeDb` (worker/db-node.js), `MIGRATIONS` (worker/schema.js),

function v17Copy(sourceFile, file) {
  const db = nodeDb(file);
  db.exec('CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL)');
  db.transaction(() => {
    for (const statements of MIGRATIONS.slice(0, 17)) for (const statement of statements) db.exec(statement);
    db.run("INSERT INTO meta (key, value) VALUES ('schema_version', '17')");
  });
  db.exec('PRAGMA foreign_keys = OFF');
  db.exec(`ATTACH DATABASE '${sourceFile.replaceAll("'", "''")}' AS src`);
  const tables = db.all("SELECT name FROM main.sqlite_master WHERE type = 'table' AND name NOT LIKE 'sqlite_%' AND name <> 'meta'");
  db.transaction(() => {
    for (const { name } of tables) {
      const columns = db.all(`PRAGMA main.table_info(${name})`).map((c) => `"${c.name}"`).join(', ');
      db.exec(`INSERT INTO main."${name}" (${columns}) SELECT ${columns} FROM src."${name}"`);
    }
  });
  db.exec('DETACH DATABASE src');
  db.close();
}
