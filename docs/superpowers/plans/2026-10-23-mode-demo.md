# Mode démo d'entraînement — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** ajouter au site des clients un espace démo aux données fictives. Il est séparé des vraies données, s'ouvre par une icône 🎓 et ne peut pas être confondu avec la vraie version. Supprimer aussi l'ancien « Mode démonstration » et les restes du site de test.

**Architecture :** une seconde classe de Durable Object, `DemoDO`, a sa propre base SQLite et sert l'espace démo. Le Worker d'entrée lit l'en-tête `X-Club-Espace: demo` envoyé par l'interface. Il vérifie alors la session auprès du vrai club, par un appel RPC qui renvoie l'utilisateur et la configuration du club. Puis il passe la requête à `DemoDO` avec cette identité vérifiée. L'interface garde l'espace choisi dans `localStorage` et l'efface à chaque déconnexion.

**Technologies :** Cloudflare Workers + Durable Objects (SQLite, RPC) ; Node `node:test` + `node:sqlite` pour les tests ; React 18 + zustand + lucide-react ; Vite.

**Description approuvée :** `docs/superpowers/specs/2026-10-23-mode-demo-design.md`

## Contraintes générales

- **Mise en ligne :** `npm test` puis `npm run deploy` (site des clients seulement). Plus aucun `deploy:test`.
- **Isolation :** rien de ce qui se fait en démo n'écrit dans le vrai club.
- **Comptes en démo :** refusés avec HTTP 403, le code `MODE_DEMO` et le message exact « Les comptes se gèrent hors du mode démo. »
- **`demo_mode` :** ce n'est plus un réglage. Il vaut `true` dans `DemoDO` et `false` dans le vrai club, quel que soit l'ancien réglage stocké. `PUT /api/settings` avec `demo_mode` renvoie 400 (`Paramètre inconnu : demo_mode`).
- **Comptes connus :** aucun compte aux mots de passe connus en ligne. `DEMO_ACCOUNTS` reste réservé au local.
- **Signalement (version C) :**
  - un cadre orange épais sur tout l'écran ;
  - un filigrane « DÉMO » derrière le contenu ;
  - un bandeau rayé « MODE DÉMO » avec un bouton « Quitter » en haut de chaque page ;
  - un orange proche de `#e07b00`, lisible en thème clair et en thème sombre.
- **Entrée :**
  - un bouton icône `GraduationCap` (lucide) dans la rangée `.side-user .row` d'`AppShell`, avec le titre « Mode démo (entraînement) » ;
  - en démo, le bouton devient « Quitter la démo » ;
  - la même entrée figure dans `AccountMenu`.
- **Langues :** textes d'interface en français, commentaires du code en anglais, dans le style du code existant.
- **Exports en démo :** le nom du fichier commence par `DEMO_`.
- **Titre de l'onglet en démo :** commence par `[DÉMO] `.

## Points de vigilance

- **Session expirée en pleine démo.** L'API renvoie 401 et l'écran de connexion s'affiche. La reconnexion ramène au vrai site. Assuré par `signOut`, qui efface l'espace (Tâche 5) ; vérifié à la main en Tâche 7.
- **Vraies données sous le cadre démo, ou l'inverse.** Entrer ou quitter recharge toute la page sur `/`, donc aucune page ne garde des données de l'autre espace. Vérifié à la main en Tâche 7.
- **Identité forgée par le navigateur.** Le Worker l'ignore : seul `routeApi` fournit l'identité. Test en Tâche 4.
- **Réglages réels inhabituels.** Formule annuelle sans prix, une seule salle, pas de moyen de paiement « Espèces » : le remplissage de la démo réussit quand même. Test en Tâche 2.
- **Compte désactivé dans le vrai club, ou rôle changé.** En démo, la personne perd l'accès (401), ou reçoit son nouveau rôle, dès la requête suivante. Test en Tâche 4.

### Tâche 3 : l'API de l'espace démo

**Fichiers :**
- Modifier `worker/api.js`.
- Test : `test/demo.test.js`.

**Interfaces :**
- Utilise `club.demoConfig`, `club.prepareDemo` et `club.resetDemo` (Tâche 2).
- Produit `createApi({ db, env, demo = false })`, qui renvoie `{ club, handle, init, demoContext, handleDemo }`.
- **`demoContext(tokenHash) -> null | { user: { id, name, role }, config }`.** Vrai club seulement. Renvoie `null` si la session est absente, expirée ou inactive (`club.sessionUser`).
- **`handleDemo(request, { user, config }) -> Response`.** Démo seulement.
  - Appelle `prepareDemo(config)`, puis traite la requête avec `club.userRow(user.id)` comme utilisateur connecté.
  - Ne lit jamais le cookie et ne cherche jamais de session.
  - Renvoie 401 `NON_CONNECTE` si l'utilisateur est inactif.
- **Option de route `accounts: true`.** Elle marque `/api/users*`, `/api/me/password` et `/api/admin/reset`. En démo, ces routes sont refusées avec `AppError(403, 'MODE_DEMO', 'Les comptes se gèrent hors du mode démo.')`, y compris `/api/admin/reset`.
- **Nouvelle route `POST /api/demo/reset` (`ADMIN`).** En démo, elle appelle `club.resetDemo(ctx.demoConfig, ctx.user)` et renvoie `club.bundle(ctx.user)`. Sur le vrai club, elle renvoie 404.
- **`respond`.** En démo, le nom des fichiers exportés commence par `DEMO_`.

- **`routeApi(request, { real, demo }) -> Promise<Response>`** dans `worker/space.js`, avec `SPACE_HEADER = 'x-club-espace'`.
  - `real` fournit `{ handle(request), demoContext(tokenHash) }`. `demo` fournit `{ handleDemo(request, ctx) }`.
  - La requête va à `real.handle` si l'en-tête ne vaut pas `demo`, ou si le chemin correspond à `^/api/(login|logout|setup)(/|$)`.
  - Sinon, le routeur calcule l'empreinte du cookie `sid` (`sha256Hex`) et appelle `real.demoContext`.
  - Si le résultat est `null`, il répond 401 en JSON : `{ error: { code: 'NON_CONNECTE', message: 'Session expirée : veuillez vous reconnecter.' } }`.
  - Sinon, il appelle `demo.handleDemo(request, ctx)`.
- **Harnais : `class Site { constructor(real, demo); fetch(url, init) }`.** Il passe par `routeApi` avec les API de deux `Server`. `Client` fonctionne dessus sans changement.
- **`worker/index.js` :**

  - `ClubDO` expose `demoContext(tokenHash)` en RPC ;
  - `fetch` appelle `routeApi` avec `real = { handle: (r) => clubStub.fetch(r), demoContext: (h) => clubStub.demoContext(h) }` et `demo = { handleDemo: (r, c) => demoStub.handleDemo(r, c) }`.
- **`wrangler.jsonc` :**
  - ajouter la liaison `{ "name": "DEMO", "class_name": "DemoDO" }` et la migration `{ "tag": "v2", "new_sqlite_classes": ["DemoDO"] }` ;
